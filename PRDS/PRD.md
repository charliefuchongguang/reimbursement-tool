# 产品需求文档（PRD）

> 项目名称：招标代理公司出差报销辅助工具（Reimbursement Helper）
> 版本：v1.0
> 状态：✅ 已确认

---

## 一、产品概述

本产品是一款面向**招标代理公司出差人员**的**报销自查与归档辅助网页工具**。在提交正式报销单之前，由出差人员本人在本地浏览器中运行，自动识别本次出差的发票（PDF + XML），做合规性自查，按公司规则归档到本地文件夹，并套用公司差旅费报销单模板 Excel 自动填好金额，导出可直接提交的报销材料。目标是把原本 1~2 小时的手工整理工作缩短到 5 分钟以内，并降低因不合规返工的风险。

---

## 二、核心功能需求

### 功能1：指定发票来源文件夹（F1）
- **描述**：用户选择一个本地文件夹，工具批量读取其中所有发票文件（.pdf / .xml）。
- **用户操作**：点击首页「选择发票文件夹」按钮 → 浏览器调用 `showDirectoryPicker()` 弹出文件夹选择器 → 选中后自动扫描。
- **预期结果**：页面显示该文件夹下扫到的发票文件列表（文件名 + 大小 + 类型），底部显示"共 X 张 PDF + Y 个 XML"。

### 功能2：自动识别发票内容（F2）
- **描述**：对每张发票做信息抽取：XML 直接解析；文本型 PDF 抽文字；两种原料再送 DeepSeek API 做字段清洗、分类和关键字段归一化。
- **用户操作**：选完文件夹自动触发，或用户点击「开始识别」按钮触发。
- **预期结果**：
  - 进度条显示识别进度（每张发票识别到哪一步）
  - 识别完后，在页面上以表格形式显示每张发票的：**类别、发票号码、开票日期、金额（含税）、销售方、备注、是否有配套 XML、识别置信度**
  - 识别失败/无法识别的单独高亮，提示用户手动补录或换文件
- **特殊规则**：
  - ⚠️ 火车票**仅 PDF 无 XML**，视为合法，不报错
  - ⚠️ 扫描件/图片型 PDF 无法抽文本，**不支持**，提示用户手动录入金额+类别

### 功能3：自动分类归档（F3，使用 File System Access API）
- **描述**：在用户选择的"输出根目录"下，按公司规则建好文件夹结构，把发票文件**复制**过去（不删原文件）。
- **用户操作**：识别完成后点击「归档 + 生成报销单」按钮 → 浏览器调用 `showDirectoryPicker({mode:'readwrite'})` 让用户选输出目录（可与源目录相同）→ 自动创建子文件夹并复制文件。
- **预期结果**：在用户指定的"输出根目录"下创建文件夹树：
  ```
  <报销人>+<报销总额>+<项目简写>/
  ├── 01_交通费/         （火车票 PDF、机票 PDF+XML）
  ├── 02_打车费/
  │   ├── 行程单/        （所有打车行程单 PDF 都放这里）
  │   ├── xxx.pdf
  │   └── xxx.xml
  ├── 03_住宿费/         （水单 PDF 也复制进来）
  ├── 04_复印装订费/
  ├── 05_专家评审费/
  ├── 06_办公用品费/
  ├── 07_餐饮费/
  ├── 08_会议费/
  ├── 09_快递费/
  └── 10_其他费用/        （退票手续费、改签费等无法归类的）
  ```
- **技术依赖**：浏览器需支持 `File System Access API`（仅 Chrome ≥ 86 / Edge ≥ 86）；不支持时给出明确提示「请使用 Chrome 或 Edge 浏览器」。

### 功能4：交通费链路校验（F3.5）
- **描述**：对识别出的"交通费"类发票按时间排序，校验首尾是否均为北京。
- **用户操作**：无需操作，自动运行；结果展示在"问题清单"里。
- **预期结果**：
  - ✅ 首张出发地=北京 **且** 末张到达地=北京 → 通过
  - ❌ 否则在问题清单提示「交通费链路异常：首张/末张不是北京，请检查是否缺失发票」
  - 允许多城市连续行程（北京→A→B→北京），中间段不强制校验

### 功能5：合规性自查（F5，必做）
- **描述**：按公司报销规范自动检查，给出问题清单。
- **用户操作**：识别完成后自动运行；用户在「问题清单」面板查看与修正。
- **预期结果**：显示所有问题项，每条可点击跳转到对应发票行。
- **检查规则表**：

| 检查项 | 规则 | 提示文案 |
|---|---|---|
| 机票备注 | 备注栏须含：①乘机人 ②行程(出发+目的地) ③时间 ④航班号 | 「第 X 张机票备注缺少 [字段]」 |
| 住宿费备注 | 备注栏须含：①住宿人 ②入离时间 | 「第 X 张住宿发票备注缺少 [字段]」 |
| 住宿水单 | 每张住宿费发票对应目录下须有"水单/账单明细"文件 | 「住宿发票 [xxx] 缺少水单附件」 |
| 电子发票完整性 | 除火车票外，每张 PDF 须配套 XML | 「发票 [xxx] 缺少 XML 原件」 |
| 专票适用性 | 餐饮/礼品/替票 之外类别，若开成普票则提示 | 「建议将 [xxx] 改开专票」 |
| 专家评审费 | 检出此类别即提示 | 「公司转账的专家费需贴专家签名表」 |
| 预付卡发票 | 识别到即警告 | 「预付卡发票会代扣 20% 个税，建议避免」 |
| 替票 | 识别到非规范类别即提示 | 「需另附说明表备注实际费用」 |

### 功能6：生成报销单 Excel（F4）
- **描述**：基于公司模板 `notes/新差旅费报销单-2025-11-14.xlsx`，自动填入各字段并导出。
- **用户操作**：在「归档 + 生成报销单」按钮触发后，连同归档操作一并执行；浏览器下载填好的 Excel 到归档根目录或下载目录。
- **预期结果**：下载一个新的 `.xlsx`，**完全保留模板原有格式 / 合并单元格 / 样式 / 公式**，填入字段如下表。

**字段映射（模板单元格 → 数据来源）：**

| 单元格 | 字段 | 来源 |
|---|---|---|
| D3 | 部门 | localStorage（首次手填） |
| F3 / J3 / K3 后 | 年/月/日 | 默认今天，可改 |
| O3 后 | 代理费及标书款 | 用户手填（可空） |
| E4 | 出差人 | localStorage（首次手填） |
| N4 | 出差事由 | 用户每次手填 |
| 行 7-16 的 B-I 列 | 交通费逐段：出发(月日时地名) / 到达(月日时地名) | F2 识别的交通类发票，按时间排序逐行填 |
| 行 7-16 的 J 列 | 交通工具 | 识别自发票：「飞机」/「火车」 |
| 行 7-16 的 K 列 | 交通费金额 | 该段发票金额 |
| 行 7-16 的 L-M 列 | 出差补助（天数 / 金额） | 按交通费起止天数计算；**70 元/天** |
| N7 `打车费（往返车站）` + O7/P7 | 张数/金额 | 行程单起终点含车站/机场关键字的打车发票 |
| N8 `打车费（市内）` + O8/P8 | 张数/金额 | 其余打车（含混合单据、无行程单） |
| N9~N15 | 住宿费/复印装订费/专家评审费/办公用品费/餐饮费/会议费/快递费 | 按类别汇总 |
| **N16** | **其他费用**（退票手续费、改签费等无法归类的） | 兜底类别 |
| K17 / M17 / P17 | 合计（交通/补助/其他） | 模板内置 SUM 公式，无需代码算 |
| N18 | 报销总额 | = K17 + M17 + P17 |
| B18（人民币大写） | 大写金额 | 代码把 N18 的数字转中文大写 |
| H18 | 予借旅费 | 用户手动填（在生成按钮旁的表单里） |
| N19 | 转账金额 | = 报销总额 |
| N20 | 补领金额 | = max(报销总额 - 予借, 0) |
| 退还金额 | （位于 O20 / P20） | = max(予借 - 报销总额, 0) |

**打车费分类判定规则：**
1. 优先用对应行程单的起点/终点文字
2. 起点或终点包含关键字【机场 / 火车站 / 高铁站 / 动车站 / 航站楼】→ **往返车站**
3. 起/终都不含车站关键字 → **市内**
4. 行程单里混合多段（既有车站也有市内）→ 统一算 **市内**
5. 没有行程单的纯发票 → **市内**（兜底）

**其他费用（兜底）判定规则：**
- AI 分类时，9 类（交通/打车×2/住宿/复印装订/专家评审/办公用品/餐饮/会议/快递）都不匹配的费用 → 统一归入「其他费用」
- 典型场景：退票手续费、改签费、行李超重费、临时打印费、签证费、误餐费等
- UI 上"其他费用"项可点开看明细，便于用户复核

## 三、交互流程

```
打开网页
  ↓
（首次）弹出设置引导：填入个人信息（部门/出差人） + DeepSeek API Key → 存 localStorage
  ↓
主页：点击「选择发票文件夹」→ 选一个本地目录（File System Access API）
  ↓
自动/手动「开始识别」→ 识别进度展示 → 识别结果表格 + 问题清单
  ↓
（可选）用户修正/删除/手动补录某些发票
  ↓
填写每次不同的字段：项目简写、出差事由、出差日期(默认今天)、代理费及标书款、予借旅费
  ↓
点击「归档 + 生成报销单」
  ↓
浏览器再次提示选「输出根目录」→ 创建归档文件夹树 → 复制发票 → 下载 Excel
  ↓
页面显示"完成"，列出归档路径 + Excel 文件名
```

**异常路径：**
- 浏览器不支持 File System Access API → 提示「请改用 Chrome 或 Edge 浏览器」
- 未配置 DeepSeek API Key → 弹窗引导去设置填 Key
- 某些发票无法识别 → 在识别表格中标红，提供"手动录入"按钮让用户补
- 输出目录无写权限 → 提示重新授权或另选目录
- 交通费链路异常 → 弹窗确认「是否继续生成？」用户可选择带着问题生成，或回去补票

## 四、数据与存储（多用户版）

- **账号与任务记录**：存储在服务端 SQLite（`server/data/app.db`），按用户隔离
- **登录凭证**：前端 `localStorage` 仅缓存 JWT 与用户信息（`reimbursement-helper.authToken` / `authUser`）
- **统一 API Key**：保存在服务端 `settings` 表，不下发前端
- **发票数据**：识别过程仅在当前会话内存中处理，**不持久化**；关闭页面即清空
- **发票文件**：仅在用户电脑本地读写；调用大模型时只传**文本内容**，不传原始 PDF/XML

## 五、边界条件与限制

- 仅支持 **Windows** 桌面版 **Chrome ≥ 86 / Edge ≥ 86**（依赖 File System Access API）
- 仅支持**文本型 PDF** + **XML**；扫描件/图片型 PDF 不支持
- 不联网（除调用 DeepSeek API 外），所有发票数据在本地处理
- 报销单 Excel **必须套用** `notes/新差旅费报销单-2025-11-14.xlsx` 原始格式，不得自定义
- 交通费仅识别往返北京的火车/机票；打车费单独分类
- 默认采用**复制（不删除原文件）**的方式归档，避免误操作

## 五-A、AI API 集成规范（DeepSeek）

### API Key 管理（多用户版，强制）
1. **严禁在代码中硬编码** API Key
2. 页面顶部齿轮图标 ⚙️ → 「设置」弹窗
3. **管理员**在设置弹窗中维护统一配置：模型、接口地址、API Key，含「测试连接」按钮；保存后写入服务端 `settings` 表
4. **普通用户**设置弹窗中不显示 Key 项，仅提示"由管理员统一配置"
5. 前端不读取、不保存 API Key；所有大模型请求经后端 `POST /api/ai/chat` 代理

### API 调用注意
- DeepSeek API 兼容 OpenAI 协议；由后端注入统一 Key 后转发
- 传给大模型的内容：发票抽取出来的**文本**（不含原始文件二进制）
- 每张发票单独调用一次 API；约 10 张发票消耗 1 分钱人民币
- API Key 无效/欠费时后端返回友好提示：「统一 API Key 无效或已过期，请联系管理员」

## 八、多用户版（v2）

在原单机版基础上新增账号体系与统一 AI 配置，业务侧（本地文件夹读写、发票识别、Excel 生成）保持不变。

### 功能1：自助注册（F6）
- **描述**：输入昵称 + 手机号 + 自定义密码（含确认密码）即注册；手机号作为登录账号
- **密码**：注册时自定义，至少 6 位；登录后**无需**强制改密
- **校验**：昵称为空/超长、手机号非 11 位、密码不足 6 位、两次密码不一致、手机号已注册均给出明确提示

### 功能2：登录验证（F7）
- **描述**：手机号 + 密码登录，后端签发 JWT（有效期 7 天）
- **前端**：未登录只显示登录页；`localStorage` 缓存 token，刷新自动恢复登录态
- **退出**：顶部导航显示昵称与管理员标签，提供退出登录按钮

### 功能3：管理员统一大模型配置（F8）
- **描述**：管理员在设置弹窗维护模型、接口地址、API Key
- **隔离**：普通用户看不到 Key；所有 AI 请求经后端代理，Key 不下发前端
- **管理员来源**：启动时由环境变量 `ADMIN_PHONE`（可选 `ADMIN_PASSWORD`）播种

### 功能4：任务记录服务端化（F9）
- **描述**：任务记录从 `localStorage` 迁移到服务端，按用户隔离、跨设备可见
- 接口：`GET/POST/PUT/DELETE /api/tasks`

### 功能5：打印合并中的行程单重构（F10）
- **背景**：财务要求打车类发票打印时后附对应行程单，但行程单为 A4，打印纸为 210×140mm 横版
- **描述**：在最后的 PDF 合并环节，将打车行程单**重构成横版**（提取汇总 + 行程表格；丢弃广告 banner/logo/二维码），代替原行程单
- **配对**：按**金额相等**（发票金额 = 行程单合计）与打车发票 1:1 配对
- **混排**：`发票合并打印.pdf` 按识别顺序排列，**每张打车发票后紧跟其重构行程单**
- **纸张**：`不拼接` = 每页 210×140mm（边距 3mm）单页；`拼接` = A4 每页 2 张
- **其他票据**：`其他票据合并.pdf` 移除打车行程单，保留机票行程单等其他类型
- **异常**：未匹配到发票的行程单重构后追加末尾并提示；未匹配到行程单的发票照常打印
- **范围**：重构仅用于打印合并文件，不改动归档目录

### 后端接口一览

| 方法与路径 | 说明 | 权限 |
|---|---|---|
| `POST /api/auth/register` | 注册（昵称+手机号） | 公开 |
| `POST /api/auth/login` | 登录，返回 JWT | 公开 |
| `GET /api/auth/me` | 当前用户 | 登录 |
| `POST /api/auth/change-password` | 修改密码 | 登录 |
| `PUT /api/auth/profile` | 更新昵称/部门/出差人 | 登录 |
| `GET/POST/PUT/DELETE /api/tasks` | 任务记录 CRUD | 登录（按用户隔离） |
| `GET/PUT /api/admin/llm` | 读取/更新统一大模型配置 | 管理员 |
| `POST /api/ai/chat` | 大模型代理（注入统一 Key） | 登录 |
| `POST /api/ai/test` | 测试统一 Key | 管理员 |
